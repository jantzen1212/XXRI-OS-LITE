# XXRI OS Lite 64-bit (x86_64)

Platform `platform-xxri64` (`ptxdist/configs/platform-xxri64`), OSELAS x86_64
toolchain (GCC 14.2.1, glibc 2.40). It builds `images/XXRI-Lite-2.6-x86_64.iso`,
one image for BIOS and 64-bit UEFI.

## How it differs from the i686 system

| | i686 | x86_64 |
|---|---|---|
| Base | Tiny Core 16 `core.gz` | `corepure64.gz` plus a `/lib64 -> lib` link |
| Kernel | Tiny Core's binary | built from Tiny Core's source and config plus `config/kernel/sof-x86_64.config` |
| Sound modules | `alsa-modules-6.12.11-tinycore.tcz` | `xxri-sound.tcz` (ALSA, SOF, SoundWire, ACP, HDA amps) |
| Extensions | `config/cde` | `config/cde64`, the x86_64 repository's own `.dep` closure |
| UEFI loader | `BOOTIA32.EFI` (i386-efi) | `BOOTX64.EFI` (x86_64-efi), also what the installer writes |
| CPU baseline | i586 (browser: SSE2) | x86-64, `-mtune=generic` |
| Firmware | lists for hardware up to ~2018 | the same plus `config/firmware/*-x86_64.list` |

The scripts are shared between the two: `xxri-mkiso.sh --arch`,
`xxri-fetch-cde.sh ... ARCH`, `xxri-tcz-sysroot.sh ... ARCH`. `XXRI_TC_ARCH`
and `XXRI_CDE_CONFIG_DIR` come from `rules/pre/xxri.make`.

## /lib64

The toolchain links every program against `/lib64/ld-linux-x86-64.so.2`, but
Tiny Core's pure64 base keeps its loader and libraries in `/lib`. Without the
link every XXRI program dies with "not found" (busybox's message for a
missing ELF interpreter). `ptxd_make_xxri_core` adds it to `core.gz`.

## Kernel and sound (SOF)

Tiny Core's kernel has no ALSA SoC (`CONFIG_SND_SOC` unset), so laptops whose
speakers or microphones sit behind an audio DSP have no sound: Intel 8th gen
and newer with digital mics or SoundWire, Ryzen with ACP mics, and many 2021+
laptops with Cirrus or TI speaker amplifiers.

`rules/xxri-kernel.make` builds the kernel from Tiny Core's
`linux-6.12.11-patched.tar.xz` and `config-6.12.11-tinycore64` plus the
fragment. Tiny Core's module packages (graphics, wireless, ...) stay in use,
so the result has to keep their ABI. `CONFIG_MODVERSIONS` is off and the kernel
won't check anything itself, so `scripts/xxri-kabi-check.py` fails the build if
a Tiny Core config value changes, a new built-in option shows up that the
fragment doesn't allow (`# xxri-kabi-allow:`), or a symbol Tiny Core's kernel
exports is missing or exported differently.

Only two additions end up in the kernel image: `REGMAP_IRQ` (CS35L41 amps and
the CS42L43 codec need it) and `GPIO_SWNODE_UNDEFINED` (CS42L43's SPI bus).
The rest of the allow list is bools compiled into sound modules.

What was checked on 2026-10-25:

- Tiny Core's config built unchanged reproduces their published `System.map`;
  only compiler-internal names differ (`CSWTCH.*` numbering, `.isra` clones).
- With the fragment the exported symbols only grow: 12 `regmap_irq` functions
  and `swnode_gpio_undefined`.
- In a VM, Tiny Core's i915, xe, amdgpu, radeon, nouveau, iwlwifi, mt7921e,
  rtw89, ath11k and btusb modules load into this kernel without ABI
  complaints, and so do the new SOF, SoundWire, ACP and amplifier modules.

Sound is all modular in Tiny Core's config and the fragment changes no
ALSA-core option, so `scripts/xxri-sound-modules.py` packs: everything under
`sound/`, the modules that exist only because of the fragment (compared with
`config/kernel/tc-built-modules-x86_64.list`), and what those depend on that
Tiny Core's packages lack (`tc-modules-x86_64.list`). That is 320 modules in
`xxri-sound.tcz`, which takes the place of
`alsa-modules-6.12.11-tinycore64.tcz` (`config/cde64/dep/alsa.tcz.dep`).

Firmware (`rules/xxri-sound-firmware.make`): Intel SOF firmware and topologies
from sof-bin 2025.01.1, the release that matches the 6.12 kernel, and the
Cirrus CS35L41/CS35L56 and TI TAS2781/TAS2563 files from linux-firmware
(`config/firmware/sound-x86_64.list`).

SOF can't be tried in QEMU, there's no DSP to emulate. It still needs a test on
a real laptop.

## CPU support

Everything XXRI builds for x86_64, including XLibre and Qt/QtWebEngine, targets
plain x86-64. It used to be `x86-64-v2`, and Xorg alone then had ~1100
SSE4/POPCNT instructions with no CPUID dispatch, so a Core 2, Athlon 64 or
Phenom got no desktop.

To check a build, look for SSE4/POPCNT instructions with objdump (only
CPUID-dispatched code may be left: glibc, Qt's drawing helpers, Chromium), then
run `tools/qa/x-test.py ISO OUT cpu-core2` (TCG Core 2 Duo; QEMU raises #UD for
instructions the model lacks).

Newer CPUs get Intel microcode from the 2026-09 release and AMD microcode for
families 10h to 1Ah (Zen 5). NVMe, Intel VMD and the LPSS I2C/SPI touchpad
controllers are built into Tiny Core's kernel.

## Firmware for current hardware

Each `config/firmware/<name>-x86_64.list` adds what the x86_64 kernel's drivers
declare (`MODULE_FIRMWARE`) for newer hardware, resolved against linux-firmware
20260810:

- `intel`: i915/xe from Ice Lake (Gen 11) to Meteor Lake, Arc (DG2), Lunar
  Lake and Battlemage.
- `amd`: amdgpu from Polaris to RDNA4 and every Ryzen APU.
- `nvidia`: nouveau's signed firmware for Pascal to Ampere. GSP-RM (~500 MB)
  is left out, so Ada and newer stay on the firmware framebuffer.
- `wireless`: Intel AX200 to BE200 with Bluetooth, MediaTek MT7921/7922/7925,
  Realtek RTW89, Qualcomm WCN6855/WCN7850.

## Test tools

- `tools/qa/x-test.py`: `kms-bios64`, `kms-x64`, `fbdev-bios64`, `fbdev-x64`,
  `apps-kvm64`, `cpu-core2`.
- `tools/qa/install-test.py`: `bios64-auto-mbr`, `x64-auto-gpt`.
- `tools/qemu-boot-test.py`: firmware `bios64` runs `qemu-system-x86_64`
  (`qemu-system-i386` can't boot a 64-bit kernel).
